Keep production on legacy reads + dual-write until a second clean Phase 5 pack
exists, then switch reads one repository at a time behind existing flags so
each flip is independently reversible. Do not remove legacy writes and do not
start Phase 7 in this plan.

### C. Phase 6 — one flag at a time

Keep `ENABLE_DUAL_WRITE=true` on every step. Enable **only** the listed flag.
Do not enable the next flag until the current one has been clean on production
and left on.

Order (do not reorder):

1. `ENABLE_NEW_CREDENTIAL`
2. `ENABLE_NEW_POINTS`
3. `ENABLE_NEW_CANDIDATE`
4. `ENABLE_NEW_LEARNING`
5. `ENABLE_NEW_PROGRESS`
6. `ENABLE_NEW_TALENT` **last**

For **each** flag:

1. Set the flag to `true` in Vercel **Production** env only (not Preview unless
   you are deliberately rehearsing). Leave every other `ENABLE_NEW_*` as it was
   (previous successful ones stay on; later ones stay off).
2. Deploy / rebuild if Vercel does not already inject env into the running
   serverless build. Confirm the deployment is Ready and the flag is present
   on that deployment.
3. Run the targeted smoke tests in the table below, as a signed-in user on
   production, exercising the live UI — not a screenshot.
4. Compare legacy vs new for a known user (SQL or a one-off read of both
   tables). Counts and displayed values must match.
5. Rerun the **relevant** drift / recon from the table. If anything is
   non-zero, set that flag back to **unset/false immediately**, redeploy, and
   stop the sequence.
6. If clean, leave the flag on. Append one changelog line:
   `YYYY-MM-DD [env] ENABLE_NEW_<NAME>=true on production after clean smoke + recon`.
7. Only then start the next flag.
